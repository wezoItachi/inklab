# INKLAB 设计语言草案

状态：讨论稿，不要求当前页面立即重做。

## 核心原则

1. **先读懂，再好看。** 主操作名称直接写清，不能只靠图标、颜色或动效猜用途。
2. **像实验工具，而不是数据海报。** 每项结论都能看到输入、状态、依据和尚未验证的边界。
3. **有限度使用品牌造型。** 紫色前层与酸绿后层组成“双色错位实验片”，用于品牌锚点和关键选择，不铺满每张普通卡片。
4. **圆角服务触控和分组。** 控件保持足够点击面积，但不同层级用尺寸、边框和留白区分，避免所有内容都变成相同胶囊。

## 双入口叙事

顶层导航可分为两个研究方向，但不强制用户经过一张入口页：

- **城市研究区**：配装实验室、能力百科、玩家方案。语气更轻松，留白更多，强调组合、比较和社区交流。
- **行动试验区**：鲑鱼跑实验室、操作实验。布局更紧凑，强调警示、测量刻度、状态灯和未验证边界。

两区共享同一品牌、颜色和基础控件，仅调整信息密度和辅助纹理，避免看起来像两个无关网站。

## 视觉语法

- 主紫：品牌、当前选择、主操作。
- 酸绿：状态确认、数据就绪、第二层错位底片；不用于长段文字。
- 深墨色：实验台、结果区和高对比标题。
- 米白：阅读背景与普通表单。
- 警示色只表达风险或待验证，不与普通装饰混用。
- 斜向错位圆角优先用于 Logo、页面编号、当前一级分区和关键实验按钮；普通筛选按钮保持易辨认的矩形或轻圆角。

## 组件优先级

- 一级：当前研究对象、执行实验、保存/分享等主要动作。
- 二级：模式、武器、标签、部位等筛选与切换。
- 三级：来源、版本、验证状态、模型边界和解释说明。
- 危险或不可逆操作必须使用文字，并与普通操作拉开位置和颜色。

## 交互规则

- 选中态同时改变填充、边框或图标，不能只靠颜色。
- 再次点击可取消的筛选必须保持一致；不可取消的主选择应明确显示当前值。
- 桌面和手机使用同一信息顺序，手机只改变排列，不隐藏关键来源与状态。
- 主要触控目标至少 44 × 44 px；键盘焦点清晰可见；弹窗可用 Escape 关闭并返回触发按钮。
- 动效只解释状态切换，不延迟输入，不用持续闪烁制造“实验感”。

## 暂不采用

- 不用品牌、装备稀有度或装备能力充当玩家方案的筛选维度。
- 不为装饰而加入大量玻璃、霓虹、噪点或倾斜文字。
- 不把“待验证”藏进脚注，也不以高精度小数制造可信感。
- 不因参考其他工具而复制其页面结构、文案或代码。
