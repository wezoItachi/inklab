# 对战武器动作周期逐帧协议（Ver. 11.3.0）

## 目的

本协议用于关闭滚筒连续横挥／竖挥与伞连续主武射击的 39 个待验证字段。上游文件中的内部动作阶段不自动等于完整连续周期；页面在逐帧证据完成前只展示动作边界，不输出连续 DPS。

## 通用采集条件

- 固定 Ver. 11.3.0，记录武器、训练场景、录像设备与实际帧率。
- 录像必须为稳定 60 fps，或记录并换算经验证的其他帧率；不得把可变帧率录屏直接当作逐帧证据。
- 站立于平地，不使用装备能力、跳跃、转向、潜墨取消或墨水回复。
- 每组先完成一次起手，再连续记录至少 10 个相同动作周期；计算释放帧到下一释放帧的逐周期差值并保留原始帧表。
- 至少复测 3 组。所有组的中位数必须一致；若存在 1 帧抖动，保留分布与不确定度，不只写单一整数。

## 动作边界

### 滚筒横挥

持续进行最快合法横挥。以第 N 次主要墨滴实际生成／释放的首帧为起点，以第 N+1 次同一事件的首帧为终点。上游 `SwingFrame` 只作为内部阶段交叉检查，不作为周期答案。

### 滚筒竖挥

持续进行最快合法竖挥。使用与横挥相同的释放到释放边界。首次跳跃、落地硬直和横挥混入样本全部剔除。

### 伞连续主武射击

重复点按主武射击，不长按进入开伞或伞面发射。以每轮散弹实际生成／释放的首帧为周期边界。开伞、发射、伞面恢复、空中射击与潜墨取消属于其他状态，不计入本字段。

## 证据记录

每条结果至少保存：武器 ID、动作、录像文件哈希或可复核链接、起止帧、连续 10 周期帧差、3 组统计、观察者和日期。原始证据与计算结果必须能相互追溯。

## 通过门槛

只有在动作事件边界可重复识别、3 组中位数一致、异常帧有说明且没有混入排除状态时，字段才可从 `pending` 改为 `verified`。墨水回复、回墨锁、AP、移动取消与空中状态均另行验证，不由本协议推导。
